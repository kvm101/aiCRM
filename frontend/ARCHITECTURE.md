# aiCRM Frontend Architecture

## Overview
Фронтенд додатка **aiCRM** побудований на базі **Next.js (App Router)** з використанням **TypeScript**.
Архітектура орієнтована на забезпечення максимальної продуктивності, швидкої реакції інтерфейсу (через оптимістичні оновлення) та підтримки роботи в реальному часі (WebSockets).

## Технологічний Стек (Tech Stack)
- **Core**: React 18, Next.js (App Router).
- **Мова**: TypeScript (строга типізація всіх DTO та пропсів).
- **Стилізація**: Tailwind CSS.
- **UI Компоненти**: shadcn/ui (Radix UI) — доступні, кастомізовані компоненти без прив'язки до важких бібліотек.
- **Управління станом (Data Fetching)**: React Query (TanStack Query) — для кешування, фонового оновлення та мутацій даних з API.
- **Глобальний стан (Global State)**: Zustand — використовується для управління станом глобального AI-чату (`useAIStore.ts`).
- **Drag & Drop**: `@dnd-kit` — для функціоналу Kanban-дошки.
- **HTTP Клієнт**: Axios (`apiClient.ts` з перехоплювачами для обробки помилок авторизації).

## Архітектурний Патерн: BFF (Backend-For-Frontend)
Фронтенд взаємодіє з Java Spring Boot бекендом за змішаною моделлю:
1. **Прямі API-виклики (Direct API Calls)**: Більшість CRUD-операцій (управління клієнтами, задачами, профілем) виконуються клієнтськими компонентами безпосередньо до бекенду через `apiClient.ts`.
2. **Server Actions / API Routes (BFF)**: Складні агрегації даних (наприклад, для Dashboard чи Reports) можуть виконуватися на стороні Node.js сервера (Next.js Server Components), щоб зменшити кількість запитів з браузера і віддавати готовий HTML.

```text
│   │   ├── page.tsx      # Головний дашборд (Dashboard)
│   │   ├── contacts/     # Сторінка CRM (Клієнти)
│   │   ├── deals/        # Сторінка управління угодами (Deals) та історією взаємодій
│   │   ├── kanban/       # Kanban-дошка завдань
│   │   ├── chat/         # Інтерфейс оператора для спілкування (Telegram)
│   │   ├── reports/      # Аналітика та звіти
│   │   └── mail/         # Відправка email
│   ├── layout.tsx        # Кореневий Layout (ініціалізація провайдерів, GlobalAIChat)
│   └── login/            # Сторінка авторизації
├── components/           # Перевикористовувані React компоненти
│   ├── ui/               # Базові компоненти (shadcn/ui: Button, Input, Dialog, etc.)
│   ├── ai/               # Компоненти штучного інтелекту (GlobalAIChat.tsx)
│   ├── kanban/           # Специфічні компоненти для Kanban (Column, TaskCard)
│   └── layout/           # Структурні елементи (Sidebar, Header)
├── hooks/                # Кастомні React Hooks
│   ├── useSales.ts       # React Query хуки для роботи з клієнтами, угодами та задачами
│   ├── useNotifications.ts # React Query хуки для системи сповіщень
│   ├── useChatWS.ts      # WebSocket хук для підключення до бекенду (Real-time чати)
│   └── useAIStore.ts     # Zustand store для AI чату
├── services/             # Сервіси для роботи із зовнішніми ресурсами
│   └── apiClient.ts      # Налаштований інстанс Axios (базовий URL, interceptors)
└── public/               # Статичні файли (зображення, іконки)
```

## Ключові Архітектурні Рішення

### 1. Глобальний AI-асистент (Global AI Chat)
Асистент інтегрований у кореневий `layout.tsx`. Це означає, що він доступний на будь-якій сторінці CRM. 
Він не втрачає контекст розмови при переході між сторінками завдяки глобальному стору `Zustand`.
Запити до AI йдуть на ендпоінт бекенду `/ai/chat`, який (через Spring AI + MCP) може виконувати мутації бази даних (створювати задачі, клієнтів), результати яких автоматично підтягнуться в UI через інвалідацію кешу React Query.

### 2. Реальний час (WebSockets)
Для модуля комунікацій (чат з клієнтами через Telegram) використовується кастомний хук `useChatWS.ts`. 
Він встановлює WebSocket з'єднання з Spring Boot бекендом. Коли клієнт пише в Telegram, бекенд отримує вебхук і миттєво пушить повідомлення через WebSocket у React. Фронтенд додає повідомлення в стейт без необхідності перезавантаження сторінки.

### 3. Оптимістичні Оновлення (Optimistic Updates)
У Kanban-дошці (`KanbanBoard.tsx`) при перетягуванні картки задачі (Drag & Drop), UI оновлюється миттєво (задача змінює колонку), і лише потім у фоні відправляється PATCH-запит на бекенд. Це створює відчуття миттєвої реакції системи (Zero Latency).

### 4. Відокремлення Даних від UI (React Query)
Замість `useEffect` + `fetch` для отримання даних використовується `React Query` (наприклад, `useClients()`, `useTasks()`).
Це вирішує кілька проблем:
- Уникнення "Race conditions".
- Кешування відповідей.
- Автоматичне оновлення даних при поверненні на вкладку браузера (Refetch on window focus).
- Глобальна інвалідація (коли AI або користувач створює клієнта/угоду, кеш інвалідується і списки оновлюються на льоту).

### 5. Система сповіщень
Для інтеграцій та повідомлень реалізовано поллінг-систему (long polling через React Query `refetchInterval`). Компонент `Header.tsx` використовує хуки з `useNotifications.ts`, які кожні кілька секунд опитують бекенд на наявність нових системних сповіщень. Це забезпечує оновлення UI (дзвоник з кількістю) без потреби перезавантажувати сторінку, коли приходить вхідний лід з Telegram чи Email.
